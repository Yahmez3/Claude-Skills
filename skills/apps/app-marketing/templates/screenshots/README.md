# Screenshot composition guide

First 3 screenshots = your conversion. Spend more time on these than on the app icon.

## Rules

1. **Text-first.** The big headline is readable at thumbnail size. Use 72-96pt for the primary claim.
2. **One idea per screenshot.** If a user can't summarize it in 3 seconds, it's too much.
3. **Device frame or not** — either is fine, but be consistent across all 10.
4. **Background color** — pick 2 palettes (primary + secondary). Rotate for visual variety without chaos.
5. **No fake data.** Real app states photograph better and don't risk policy rejection.
6. **Localize** the text overlays for every priority market (es-MX, de-DE, ja-JP).

## Recommended sequence

| # | Purpose | Copy pattern |
|---|---|---|
| 1 | Big promise + proof | `{{ outcome user wants }} — {{ one proof point }}` |
| 2 | Core interaction | `{{ verb }} in {{ small number }} taps` |
| 3 | The differentiator vs incumbent | `Unlike {{ alternative }}, no {{ pain }}` |
| 4 | Feature 1 | `{{ verb }} {{ noun }}` |
| 5 | Feature 2 | same |
| 6 | Feature 3 | same |
| 7 | Use case variety | `Works on {{ use case A }}, {{ B }}, {{ C }}` |
| 8 | Trust / security / privacy | `{{ claim }} — {{ proof }}` |
| 9 | Testimonial or press | direct pull-quote |
| 10 | Final CTA / "get started" | `{{ verb }} today` |

## Tools

- **Figma** — the community files `App Store Screenshots` / `Play Store Screenshots` are a good starting frame
- **Screenshot.rocks, Shotbot, Previewed** — for framing + localization batches
- **Rotato, Screenshot Creator** — 3D mockups if your audience is design-lead

## QA

- Color contrast of overlay text ≥ 4.5:1 against background
- Thumbnails (tap on listing to preview) don't clip the headline
- First screenshot legible at 120px wide (how it appears in search results)
